# Judge review #2: after the Stage 0A hard-stop fixes (2026-11-18)

Verdict: **proceed after fixes.** Confidence: medium-high on the code findings (the judge ran them against the built `dist/arima-hook.mjs`, a mutation copy of the repository, and the scanner); low on how Claude Code's own permission rules behave, which it could not test offline. Baseline it reviewed: 20 test files, 473 tests, all passing. It changed nothing in the repository.

This file keeps the findings in condensed form with the builder's response to each one. Nothing was ignored. Status words: **Fixed** (code change with a test), **Fixed in 114e104** (the guard rewrite commit that was written in response to this report, before this file existed), **Docs** (the claim was corrected), **Open** (planned, with where), **Spec issue** (needs the owner). The next judge checkpoint re-runs the bypass corpus and the mutations rather than trusting this table.

## Blockers

| # | Finding | Response |
| --- | --- | --- |
| 1a | The guard fails open when its 10 s timeout kills it: the block path awaited an event-log write, and an agent could hold `.arima/events.jsonl.lock`, so the hook ran past 10 s and the push went through | **Fixed in 114e104.** The block is returned before the log is written (best effort, short wait), and `*.lock` files under `.arima/` are protected. Executed test: a held lock cannot turn a block into an allow |
| 1b | A crash before `runHookCli` runs (missing or corrupt bundle, Node too old) exits 1, which is not a block | **Fixed in 114e104.** `hooks/guard.sh` launches the bundle and turns any exit code other than 0 or 2 into exit 2, inside an ARIMA project only. Executed tests cover a missing bundle and a crashing guard |
| 1c | The POSIX launcher fails open if Claude Code ever runs hooks under PowerShell | **Open, stated.** The command is `sh "…/guard.sh"`, so it works wherever `sh` exists (Git Bash on Windows, as in the live check). If `sh` itself is missing, the shell reports "command not found", which is not exit 2. Recorded in ADR-0005 as an assumption; the latency and shell checks are in S0.9 |
| 1d | Notion and the remote state branch both unreachable: the kill-switch check returns "not paused" | **Open, by the spec.** Spec §7 says work continues when Notion is down, and the local `PAUSE` file is still honoured. Principle 10 says fail closed. This is spec issue material for the owner; the preflight reports the outage as a warning. The dispatch now also re-checks (see M9 below) |
| 2 | Simple bypasses of the git/gh guard (`git checkout main && git push origin HEAD`, quoting tricks, `$(…)`, combined flags `-fu`, `commit -nm`, `--receive-pack`, `git diff --output=…`) | **Fixed in 114e104.** The guard was rewritten around a tokenizer that splits commands the way the shell does, expands simple quoting and variables, tracks the current branch for `push HEAD`, handles combined short flags and file-writing git options. A bypass corpus (the judge's table) runs as a test. **Not claimed:** forms the tokenizer cannot see (`$(…)` of something dynamic, child processes) are blocked as "dynamic" when they touch a push, but a script the agent writes and runs is outside the guard (see 3) |
| 3 | The role allow-lists do not constrain developer and QA, so the local "hard stop" tests cannot prove the stop (`package.json`, `.git/**`, `.husky/**`, `.mcp.json` and test files are writable and then run by `npm test`) | **Docs, Spec issue.** Accepted as true. The guides now say plainly that the local layers are **advisory for developer and QA** until a sandbox or GitHub branch protection exists (BUILD-GUIDE §1, PRODUCT-GUIDE §7). The real barriers are S0.5 (branch protection, with the GitHub Free caveat), WSL 2 or Linux for unattended runs (S6), the Docker sandbox design (D-36), and new spec issue S16: agents never hold push credentials, a host script pushes and opens pull requests |

## Gaps the judge listed that nobody owned, and who owns them now

1. Guard fail-open on timeout, crash, non-bash hook shell: fixed in 114e104 except the missing-`sh` case (1c).
2. Credential files outside `.env` and `Grep`/`Glob` reads: fixed in 114e104.
3. Windows case, traversal and stream handling: fixed in 114e104.
4. Developer and QA code-execution paths: documented as advisory; S0.5, S6, S16 and the Docker sandbox design own them.
5. A Notion re-check at dispatch and a loud state-push failure: fixed in this batch.
6. Privacy "unknown" policy and the scanner exception path: fixed in this batch and 114e104.
7. `arima-notion push` gating: fixed in this batch (Status); role check open.

## New spec-issue and ADR candidates from this review

- **S16** agents never hold push credentials; a host script pushes branches and opens pull requests (`docs/process/spec-issues.md`).
- **S17** the QA role has `npx playwright`; replace with a pinned local binary, and state the exception until then.
- The Docker sandbox (D-36) is the long-term answer to finding 3; it needs a long-lived Claude token and is designed in Stage 0 step E.
