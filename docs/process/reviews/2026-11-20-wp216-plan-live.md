**A bug only the real workspace could show:** the mirror stores a relation as page ids (UUIDs), not row ids. The first version compared `MS-01` with those UUIDs, so the second plan said "already in 41d0c75b-…" and a revision of `MS-01` would never have recognised its own stories. `storiesForPlan` now names relation values by row id through the mirror (`page_id` to `id`), with a test that uses page ids (the fake mirror in the other tests used row ids, which hid it).

**Left in the dev workspace:** `US-001` to `US-005` and `MS-01` (no retire status for milestones; the stories' `Status` cannot be retired without the engine). Ids may be reused by a later scratch counter.
